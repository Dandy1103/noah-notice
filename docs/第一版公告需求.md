# NOAH 內網公告功能需求

NOAH 的公告模組讓員工提交公告、追蹤自己的申請，並由公告管理員審核。**公告核准後立即上架，只有指定對象看得到。上架後持續保留供同仁查閱，有需要時由管理員手動下架。**

第一版以**全員可申請、一層審核**為設計前提。公告管理員可以是同一個角色，負責審核和下架。

## 角色與權限

| 角色 | 可以做什麼 |
|---|---|
| 員工 | 依公告對象瀏覽已上架公告、提交公告申請、查閱自己的申請與審核結果、修改退回的案件並重新送審 |
| 公告管理員 | 查看待審案件、核准並上架、填寫原因後退回、查閱已處理案件、手動下架已刊登公告 |

「我的申請」只顯示本人提交的案件。審核、下架、申請詳情和公告詳情都要由 API 檢查權限，包含直接開啟詳情連結的情況。

## 公告流程

| 狀態 | 如何進入 | 接下來可以做什麼 |
|---|---|---|
| 待審核 | 員工送出表單，或修改退回的案件後再次送審 | 申請人可查看送出的內容。管理員可核准或退回。 |
| 已退回 | 管理員選擇「退回修改」並填寫原因 | 申請人可查看原因，修改同一筆申請後重新送審。 |
| 已上架 | 管理員選擇「核准並上架」 | 系統記錄審核人、審核時間和刊登時間，指定對象即可查看公告。 |
| 已下架 | 管理員手動下架 | 公告從員工列表和詳情入口移除。管理員仍可查閱紀錄，申請人仍可在「我的申請」查看原內容、刊登時間和下架時間。 |

## 頁面與欄位

| 頁面 | 欄位與操作 |
|---|---|
| **公告申請** | 必填 **主旨、內文、公告類型、公告對象**，附件選填。申請人、申請單位由登入資料帶入，送審時間由系統記錄。送出成功後進入該筆詳情，顯示「已送出，等待審核」。 |
| **我的申請** | 列表顯示 **主旨、送審時間、狀態**。點主旨查看送審內容和處理結果。退回時顯示原因及「修改後重新送審」，上架時提供「查看公告」，下架後仍保留申請紀錄。 |
| **申請處理** | 預設顯示待審案件，列表放 **主旨、申請人／單位、公告對象、送審時間、查看**。審核詳情顯示類型、對象、內文和附件，底部提供「核准並上架」與「退回修改」。已處理的案件可查審核結果、審核人、審核時間和退回原因。 |
| **公告管理** | 管理員查詢已上架與已下架的公告。列表放 **主旨、申請單位、類型、對象、刊登時間、狀態**，已上架的案件提供「下架」操作。 |
| **員工公告列表與詳情** | 沿用 **營運公告、活動、制度、人事**四個類別。列表顯示主旨和刊登日期，詳情顯示內文和附件。公告對象可選全體同仁或指定部門。 |

## 目前畫面的調整

- **「公告發布」改成「公告申請」**，在同一個入口提供「新增申請」和「我的申請」。
- **日期保留「送審時間」與「刊登時間」**。待審案件只有送審時間，核准後由系統填入刊登時間。第一版省略預約刊登和自動下架，活動日期、報名截止等資訊放在公告內容。
- **精簡待審列表和審核視窗**。待審列表省去每列都相同的狀態與審核人，編號移到詳情。審核視窗把內文往上移，讓審核人打開就能看到主要內容。發文字號等有正式編號需求再加。
- **把已刊登公告的「刪除」改成「下架」**，保留申請與審核紀錄，讓申請人日後仍能確認自己送過什麼、何時通過，以及公告目前是否還在架上。
